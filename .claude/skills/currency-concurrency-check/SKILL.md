# 재화/동시성 점검 체크리스트

코드를 읽고 아래를 항목별로 `OK / 문제 / 해당 없음`으로 판정한다. 문제는 파일:라인과 재현 시나리오를 함께 적는다.

1. 같은 플레이어 행을 변경하기 전에 `findForUpdate`(PESSIMISTIC_WRITE)로 잠그는가?
2. 잠금 순서가 `플레이어 → 하위 엔티티`로 일관된가? (데드락 가능성)
3. 잔액 검증과 차감이 **같은 트랜잭션** 안에서 일어나는가? (check-then-act 분리 금지)
4. 모든 재화 증감이 `CurrencyLedgerService`를 통해 원장에 남는가? 직접 setter 호출은 없는가?
5. 같은 요청이 두 번 들어와도(더블 클릭, 재시도) 보상이 두 번 지급되지 않는가? (상태 전이 또는 유니크 제약)
6. 클라이언트가 보낸 수량·가격·보상 값을 그대로 쓰지 않고 정적 데이터로 서버가 계산하는가?
7. 음수/0/오버플로우 입력이 검증되는가?
8. Redis 갱신(랭킹 등)이 `AFTER_COMMIT`에서 일어나 롤백 시 불일치가 생기지 않는가?

문제가 있으면 수정안과 이를 검증할 동시성 테스트(스레드 N개 동시 요청) 초안을 함께 제시한다.
