# UI 아트 AI 작업 가이드 및 프롬프트

## 목적

아트디렉터 없이도 AI가 이 프로젝트의 UI 시안과 아트 리소스를 일관되게 제안·제작하도록 하는 작업 기준이다. 목표 인상은 **캐주얼하지만 세련된 모바일 게임 UI**다. 캐주얼함은 게임 콘텐츠 아이콘과 짧은 반응에서, 세련됨은 명확한 정보 위계·일정한 여백·절제된 강조색에서 만든다.

이 문서는 새로운 스타일 방향과 AI 작업 절차를 정한다. 실제 Unity UI의 크기와 배치는 화면 캡처로 확인해야 한다. 아래 값은 제작 기준이며, 시안을 승인하기 전까지 구현 완료 상태를 뜻하지 않는다.

## AI에 제공할 자료와 우선순위

1. 작업 대상의 **현재 게임 화면 캡처**와 필요한 상태별 캡처. 실제 배치와 콘텐츠의 기준이다.
2. `Assets/UIReferences/Main/`, `Assets/UIReferences/Battle/` 및 각 `UIReferencesGuid.md`. 기능·정보 구조의 기준이다. 레퍼런스의 외형을 그대로 복제하지 않는다.
3. `Docs/Guide/UIStyleGuide.md`, `Docs/Guide/GUIPack_CleanMinimalist.md`. 현재 팔레트, 캔버스 기준, 활용 가능한 팩의 기준이다.
4. 해당 UI 프리팹과 기존 아이콘. 화면에 이미 쓰이는 요소와 재사용할 요소를 확인한다.

자료 사이에 차이가 있으면 **현재 화면의 기능·내용과 레퍼런스 가이드의 기능 설명을 먼저 보존**한다. 외형에는 이 문서의 방향을 적용한다. 실제 화면을 확인하지 못한 부분은 추정이라고 표시하고, 없는 기능이나 보상을 시안에 추가하지 않는다.

## 시각 규칙

### 색과 면

다크 테마를 기준으로 한다. 기존 팔레트를 출발점으로 사용하고, 시안에서 바꿀 값은 변경 전후를 명시한다.

| 역할 | 기준색 | 사용 규칙 |
|---|---|---|
| 헤더·깊은 배경 | `#1C232A` | 가장 뒤 또는 팝업 상단 |
| 기본 패널 | `#2C3642` | 정보 묶음의 면 |
| 경계·구분선 | `#374355` | 얇게 사용 |
| 기본 글자 | `#FFFFFF` | 제목·핵심 값 |
| 보조 글자 | `#C9D3DF` | 설명·보조 값 |
| 주요 행동·선택 | `#FFB700` | 한 화면의 가장 중요한 버튼 또는 선택 상태 |
| 일반 행동 | `#455D73` | 보조 버튼 |
| 위험·HP·경고 | `#FA5252` | 게임 의미에 맞을 때만 |
| 경험치·정보 | `#339AF0` | 게임 의미에 맞을 때만 |

등급색, 승리·패배색 등 기존에 의미가 정해진 색은 `Docs/Guide/UIStyleGuide.md`를 따른다. 색만으로 상태를 설명하지 말고 텍스트, 모양, 잠금·체크 표시를 함께 쓴다. 면은 단색을 기본으로 하고, 그림자는 떠 있는 팝업과 주요 버튼에만 얕게 적용한다. 장식용 그라디언트와 두꺼운 검정 외곽선은 쓰지 않는다.

### 형태·간격·글자

- 패널·버튼·카드·슬롯은 둥근 사각형 계열로 통일한다. 동일 역할에 동일한 모서리, 테두리, 내부 여백을 쓴다. 배너와 제목은 복잡한 리본 장식보다 글자 크기와 면의 밝기 차이로 구분한다.
- 캔버스 기준은 **1080×1920 세로형**이다. 기준 크기와 버튼·터치 영역은 `Docs/Guide/UIStyleGuide.md`의 5~6장을 확인한다. 작은 장식보다 터치 가능 영역과 읽기 쉬운 글자가 우선이다.
- 제목·버튼은 보유 중인 `NanumGothicBold SDF`를 기준으로 한다. 본문·설명은 보유 중인 `Pretendard-Regular SDF`를 실제 화면에서 비교한 뒤 채택 여부를 결정한다. 숫자 전용 텍스트에는 기존 팩의 Roboto를 사용할 수 있다. 한글이 포함된 문구에 Roboto만 지정하지 않는다.
- 텍스트는 이미지에 굽지 않는다. 시안 이미지를 만들 때 텍스트가 정확히 렌더링되지 않으면 빈 텍스트 영역과 별도의 문구 목록을 제공한다. 최종 글자는 Unity UI에서 배치한다.

### 아이콘과 아트 가공

| 종류 | 대상 | 규칙 |
|---|---|---|
| 조작 아이콘 | 닫기·뒤로가기·설정·음소거 등 | Clean & Minimalist 팩의 단색 아이콘 계열로 통일. 버튼 안의 그림 크기와 여백을 맞춘다. |
| 콘텐츠 아이콘 | 장비·스킬·재화·보상 등 | 기존 컬러와 그림체를 유지. 공통 슬롯·배경·그림 크기·배지 위치로 목록의 통일감을 만든다. |
| 상태 표시 | 등급·잠금·선택·알림 등 | 공통 배지와 테두리 규칙을 사용. 아이콘 전체를 상태색으로 덮지 않는다. |

아이콘 작업 순서는 **투명 여백 정리 → 실제 그림의 크기 맞춤 → 공통 슬롯에 배치 → 튀는 항목만 교체**다. `Assets/Resources/Skill/Icons/`처럼 작은 픽셀 표현의 아이콘은 확대 사용 전에 선명도를 확인한다. 새 아이콘이 필요한 경우 주변 아이콘의 외곽선 두께, 시점, 채색 밀도를 기준 이미지로 함께 제공한다.

팩 리소스는 `Assets/Externals/GUIPack-Clean&Minimalist`에 있다. 팩을 참조한 결과물은 팀원의 로컬 환경에서도 열리는지 확인한다. 팩 원본 파일을 프로젝트의 다른 경로로 복사해 재배포하지 않는다.

### 반응

버튼 누름·팝업 등장·보상 획득처럼 행동의 결과를 알려주는 곳에만 짧은 애니메이션을 쓴다. 기존 `ButtonFeedback`과 `UITween`의 반응을 우선 확인한다. 장식 목적의 상시 점멸과 확대는 피한다. 전투 중 일시정지 상태에서도 UI 반응이 정상적으로 보여야 한다.

## 작업 순서와 산출물

| 순서 | AI 작업 | 산출물 |
|---|---|---|
| 1 | 현재 화면·상태·사용 리소스 분석 | 바꾸지 말아야 할 기능과 정보, 시각적 문제, 확인되지 않은 부분 |
| 2 | `BattleTab`, `InventoryTab`, `MessagePopup`의 스타일 탐색 | 같은 규칙을 적용한 1080×1920 시안 3종 및 상태별 변형 |
| 3 | 팀이 선택한 시안을 기준으로 규격 고정 | 색·글자·간격·버튼·카드·슬롯·배지 규격표와 아이콘 가공 규칙 |
| 4 | 공통 요소와 나머지 화면에 확장 | 화면별 시안 또는 교체할 개별 PNG 목록. 기능 변경 사항은 별도 표시 |
| 5 | 실제 Unity 화면과 비교 | 차이 목록, 긴 한글·큰 숫자·작은 화면·노치·전투 배경 위 HUD 검수 결과 |

첫 시안에서 기능을 유지한 채 시선 순서를 점검한다. `BattleTab`은 **스테이지 → 게임 시작 → 보조 메뉴**, `InventoryTab`은 **캐릭터·장착 상태 → 보유 목록 → 상세 정보**가 읽히는지 확인한다. `MessagePopup`에서 제목·본문·닫기·확인 버튼의 공통 규칙을 정한다.

## 바로 사용할 프롬프트: 화면 시안

아래 `[ ]`를 채우고 현재 화면 캡처와 관련 아이콘을 첨부한다. 저장소를 읽을 수 있는 AI라면 경로의 문서를 직접 확인하게 한다.

```text
당신은 Unity 2D 모바일 게임 COU_Client의 UI 아트 작업자다.
목표는 현재 화면의 기능과 정보 구조를 보존하며 캐주얼하지만 세련된 다크 테마 시안을 만드는 것이다.

대상 화면: [BattleTab / InventoryTab / MessagePopup / 기타]
작업 범위: [화면 전체 / 특정 영역 / 특정 상태]
입력 자료: [현재 화면 캡처], [상태별 캡처], [관련 아이콘]
참고 문서: Docs/ETC/UIArtAI_PromptGuide.md,
  Docs/Guide/UIStyleGuide.md,
  Docs/Guide/GUIPack_CleanMinimalist.md,
  Assets/UIReferences/Main 또는 Battle의 해당 가이드

요구사항:
1. 현재 화면에 있는 행동, 문구, 재화, 상태와 정보의 우선순위를 먼저 목록으로 확인한다.
2. 1080×1920 세로 시안을 만든다. 다크 청회색 패널, 둥근 사각형,
   절제된 노란 주요 행동, 통일된 여백과 아이콘 크기를 적용한다.
3. 조작 아이콘은 단색, 장비·스킬·재화 등 콘텐츠 아이콘은 기존 컬러를 살린다.
4. 한글 문구와 숫자는 별도 텍스트 목록으로 제공한다. 이미지 생성기가
   정확한 한글을 만들지 못하면 화면의 글자 영역을 비워 둔다.
5. 현재 화면과 달라진 점을 '외형', '배치', '기능·정보'로 구분해 보고한다.
   기능·정보를 추가하거나 삭제했다면 시안에서 되돌린다.

출력: 화면 시안, 사용한 색·글자·간격·모서리 규격, 필요한 개별 아트 목록,
현재 화면 캡처를 확인하지 못해 추정한 부분.
```

## 바로 사용할 프롬프트: 개별 아이콘 가공·생성

```text
COU_Client의 [아이콘 이름]을 [사용 화면과 슬롯 크기]에 맞게 제작 또는 가공한다.
첨부한 기존 아이콘과 같은 콘텐츠 계열이다. 원본의 주제, 시점, 외곽선,
채색 밀도를 유지한다. 실제 그림이 슬롯 안에서 차지하는 크기를 주변
아이콘 [비교 아이콘 이름]과 맞춘다.

결과물은 배경이 투명한 PNG 한 개다. 슬롯·등급 테두리·배지·텍스트는
이미지에 합치지 않는다. 작은 크기로 축소한 미리보기도 함께 제공한다.
원본이 픽셀 표현이면 픽셀의 선명도와 표현 방식을 유지한다.
변경한 부분과 기존 아이콘 사이의 차이를 짧게 설명한다.
```

## 검수 기준

- 화면을 축소해 봐도 주요 행동과 현재 상태가 먼저 보인다.
- 같은 역할의 버튼·카드·슬롯·배지는 화면마다 모양과 간격이 같다.
- 조작 아이콘과 콘텐츠 아이콘의 역할이 구별되고, 같은 목록의 그림 크기가 고르다.
- 긴 한글, 큰 재화 수치, 잠금·선택·비활성 상태에서도 겹침이나 의미 손실이 없다.
- 전투 배경 위 HUD의 글자와 바가 읽히며, 노치와 화면 가장자리에서 터치 영역이 유지된다.
- 시안의 기능·문구·보상은 현재 화면 및 UI 레퍼런스의 설명과 일치한다.
