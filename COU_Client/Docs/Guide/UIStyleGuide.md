# UI 스타일 가이드

COU_Client UI를 만들거나 고칠 때 사람과 AI가 함께 따르는 기준이다. 시각 규격(1~7장)과 작업 방법(8~12장)을 담는다. Unity 도구 사용법과 작업 대기 목록은 `Docs/Guide/UIWorkflow.md`에 있다.

- 목표 인상은 **캐주얼하지만 세련된 모바일 게임 UI**다. 캐주얼함은 게임 콘텐츠 아이콘과 짧은 반응에서, 세련됨은 명확한 정보 위계·일정한 여백·절제된 강조색에서 만든다.
- 탕탕특공대 레이아웃에 GUIPack-Clean&Minimalist 에셋을 입힌다. 팩의 경로, 구조, 적용 방법은 `Docs/Guide/GUIPack_CleanMinimalist.md`를 본다.
- 기준 시안: BattleTab, InventoryTab, MessagePopup 2종 ([COU UI 시안](https://claude.ai/artifact/UnDE1cKh4nQGXLa62sfULJ), 소유자가 공유해야 열린다). 참고용이며, 이 문서와 다르면 이 문서를 따른다.

## 1. 방향
- **하이브리드**: 형태, 면 색, 조작 아이콘은 팩을 따른다. 고채도 강조색은 게임에서 의미가 큰 곳(메인 버튼, 승리·패배 배너, 보스 경고, HP)에만 쓴다.
- 레퍼런스(`Assets/UIReferences`)에서는 배치와 기능만 가져온다. 두꺼운 검정 외곽선, 사선, 리본 배너 같은 외형은 가져오지 않는다. 배너와 제목은 글자 크기와 면의 밝기 차이로 구분한다.
- **테마는 Dark를 기준으로** 만든다. Light도 검수 대상이지만 화면마다 하지 않고 작업을 모아 한 번에 검수한다.

## 2. 모양
같은 역할에는 같은 모서리, 테두리, 내부 여백을 쓴다. 스프라이트는 팩의 `Shapes/` 아래에 있다.

| 역할 | 반경 | 스프라이트 | ppuMul | 테두리 스프라이트 |
|---|---|---|---|---|
| 팝업 패널, 큰 카드 (스테이지 그림) | 32 | Semi Rounded (Sliced) | 0.94 | Semi Rounded - Stroke 2px |
| 메뉴 카드 | 24 | Semi Rounded (Sliced) | 1.25 | Semi Rounded - Stroke 2px |
| 버튼, 프로필 버튼 | 20 | Semi Rounded (Sliced) | 1.5 | 없음 |
| 배지, 재화 표시, 능력치 칸 | 알약형 | Rounded (Sliced) | 3 | Rounded - Stroke 6px |
| 아이콘 버튼 | 원 | Circle - 256 (Simple) | - | 없음 |
| 장비 슬롯 | - | 등급 프레임 이미지 (Simple) | - | 없음 |

테두리 스프라이트는 패널과 같은 ppuMul을 쓴다.

## 3. 색
- 모든 색은 단색이다. 그라디언트는 쓰지 않는다. 팩의 `Gradient` 프리팹 변형과 `Ricimi.Gradient` 컴포넌트도 쓰지 않는다.
- 면과 글자 색은 `ThemedGraphic`의 `UIColor`로 지정한다 (9.1).

### 3.1 면과 텍스트
| 역할 | 값 | `UIColor` |
|---|---|---|
| 헤더, 상단바, 탭바, 깊은 배경 | `#1C232A` | Base |
| 패널, 화면 배경 | `#2C3642` | Surface |
| 구분선, 카드·재화 표시 테두리 | `#374355` | Divider |
| 팝업 패널 테두리 | `#374355` | Border |
| 텍스트 기본 | `#FFFFFF` | Content |
| 텍스트 보조 | `#C9D3DF` | SubContent |
| Dim | `#000000B3` | - |

테두리와 구분선의 두께는 2다.

### 3.2 버튼
| 역할 | 예 | 값 |
|---|---|---|
| 메인·확인 | 게임 시작, 확인, 계속하기, 선택, 레벨업 | Yellow `#FFB700`, 글자 `#28313C` |
| 구매 | 상점 가격 버튼, 지원품 상자 열기 | 살 수 있으면 메인과 같고, 없으면 일반과 같다 |
| 위험 | 종료 | Red `#FA5252` |
| 일반 | 취소, 일괄 레벨업, 정렬, 합성, 그 밖의 버튼 | Dark `#455D73`, 글자 `#FFFFFF` |

- Yellow는 절제해서 쓴다. 가장 중요한 행동에만 쓰고, 여러 버튼이 경쟁하지 않게 한다.

### 3.3 게임 의미색
| 역할 | 값 |
|---|---|
| 플레이어 HP, 보스 HP, 보스 경고 | Red `#FA5252` |
| EXP 바, 프로필 레벨 배지 | Blue (Soft) `#339AF0` |
| 승리 배너 | Orange `#FF873A` |
| 패배 배너 | Blue `#078CE4` |

### 3.4 등급
`GradeColor.cs`와 등급 프레임(`Resources/Equip/Inven/Item/Equip/Grade/`)이 이 값을 쓴다. 등급 프레임 왼쪽 위에는 등급 표시가 있다.

| 등급 | 값 |
|---|---|
| 일반 (General) | Light `#AFBCCD` |
| 고급 (Super) | Green `#00C45D` |
| 희귀 (Rare) | Blue `#078CE4` |

Green은 등급색이므로 버튼 색으로 쓰지 않는다.

### 3.5 상태
색만으로 상태를 나타내지 않는다. 각 상태는 색과 함께 모양이나 글자를 같이 바꾼다.

| 상태 | 표시 |
|---|---|
| 선택 (탭) | 배경 Surface + 위쪽 Yellow 막대(높이 8) + 라벨 표시 + 아이콘 확대 |
| 선택 (목록 항목) | 오른쪽 위 Yellow 원 48 + `#28313C` 체크 |
| 선택 불가 (목록 항목) | 아이콘 영역 위에 `#00000099` 덮개 |
| 준비 중 (기능 없는 버튼) | 알파 0.5 + 오른쪽 위 자물쇠 아이콘 32 (`#C9D3DF`) |
| 새 소식 | Red 원 40 + "!" (Caption) |
| 버튼 비활성 | `Button`의 Disabled 색 + 누를 수 없음 |

## 4. 아이콘

### 4.1 조작 아이콘 (닫기, 뒤로가기, 탭, 메뉴, 재화 + 등)
- 팩의 흰색 단색 아이콘을 쓰고, 색은 `Image.color`로 입힌다.
- 기본은 흰색, 보조 요소는 `#C9D3DF`, 의미가 있는 곳은 3장의 색을 쓴다. Yellow 버튼 위의 아이콘은 `#28313C`다.
- 같은 줄에 놓이는 아이콘은 같은 계열(선 굵기, 채움 여부)으로 맞춘다.

| 놓이는 곳 | 칸 | 아이콘 |
|---|---|---|
| 아이콘 버튼 L / M | 원 128 / 96 | 64 / 48 |
| 탭 (보통 / 선택) | - | 72 / 96 |
| 메뉴 카드 (작은 / 큰) | 136 / 216x168 | 64 / 72 |
| 재화 표시 / 능력치 칸 | 높이 64 / 72 | 40 / 48 |
| 재화 + 버튼 | 원 48 | 28 |

### 4.2 콘텐츠 아이콘 (장비, 스킬, 재화, 보상)
- 원본의 색과 그림체를 유지한다. 공통 슬롯, 그림 크기, 배지 위치로 목록의 통일감을 만든다.
- 픽셀 그림은 Filter Mode를 Point로 둔다. 작은 픽셀 아이콘은 키우기 전에 선명도를 확인한다.
- 작업 순서: 투명 여백 정리 → 그림 크기 맞춤 → 공통 슬롯에 배치 → 튀는 항목만 교체.
- 장비 아이콘은 등급 프레임 크기의 60%로 놓고, 왼쪽 위 등급 표시를 피하도록 프레임 크기의 2%만큼 오른쪽, 4%만큼 아래로 옮긴다.

### 4.3 리소스 제작
- 슬롯, 등급 테두리, 배지, **글자는 이미지에 합치지 않는다.** 글자는 Unity에서 TMP로 배치한다.
- 새 아이콘이 필요하면 주변 아이콘의 외곽선 두께, 시점, 채색 밀도를 기준 이미지로 함께 제공한다.
- 팩 원본 파일을 프로젝트의 다른 경로로 복사해 재배포하지 않는다.

## 5. 글자

### 5.1 폰트
- 한글 텍스트는 `NanumGothicBold SDF` 하나만 쓴다. 굵기가 하나뿐이라서 위계는 크기(5.2)와 색(3.1)으로만 나눈다.
- 숫자 전용 텍스트(타이머, 재화, 킬 수, 데미지, 능력치 값)는 팩의 Roboto를 쓴다. Display 단계와 버튼 안 숫자는 `Roboto-Bold SDF`, 나머지는 `Roboto-Medium SDF`다. 한글이 섞이는 텍스트에는 쓰지 않는다.
- 모든 글자는 TMP다. 레거시 `UnityEngine.UI.Text`와 `Pretendard-Regular SDF`는 쓰지 않는다.

### 5.2 크기 단계
글자 크기는 아래 7단계만 쓴다.

| 단계 | 크기 | 쓰는 곳 |
|---|---|---|
| Display | 112 | 전투 타이머, 결과창 경과시간 |
| H1 | 72 | 스테이지 이름, 결과·보상 배너, 보스 경고 |
| H2 | 52 | 팝업·창 제목, 화면 제목, 리본 배너, L 버튼, 전투력 수치 |
| Body L | 44 | 카드 이름, 안내 문구, M 버튼 |
| Body | 36 | 본문 메시지, 수치, 재화 값, 닉네임, S 버튼 |
| Caption | 28 | 라벨, 설명, 수량, 배지, 레벨, 탭 라벨 |
| Small | 24 | 메뉴 카드 라벨, 남은 시간 |

- 여러 줄 본문(팝업 본문, 설명)은 TMP `Line Spacing` 35(약 1.5배 줄 높이), 그 밖은 0이다.
- 한글은 단어 단위로 줄을 바꾼다 (TMP Settings `Use Modern Hangul Line Breaking Rules`).
- 길이가 바뀌는 값(재화, 닉네임)은 한 줄로 두고, 넘치면 Auto Size로 최소 24까지 줄인다.
- 한 텍스트 안에서 크기나 색을 나눠야 하면 리치 텍스트를 쓴다.

## 6. 크기
- 캔버스 기준은 1080x1920(Match Width)이다.
- 크기, 위치, 간격은 4의 배수로 잡는다. 비율로 계산한 값도 4의 배수로 반올림한다.
- 버튼, 바, 카드, 슬롯, 배지의 높이는 8의 배수로 잡는다.
- 작은 장식보다 터치 영역과 읽기 쉬운 글자가 우선이다.

### 6.1 버튼
| 단계 | 높이 | 최소 폭 | 글자 | 쓰는 곳 |
|---|---|---|---|---|
| L | 144 | 360 | 52 | 게임 시작, 결과 확인, 계속하기 |
| M | 120 | 280 | 44 | 팝업 확인·취소, 종료, 선택, 도전 시작 |
| S | 96 | 180 | 36 | 패널 안 보조 버튼(장착, 레벨업, 정렬, 합성) |

### 6.2 배지
| 종류 | 크기 | 쓰는 곳 |
|---|---|---|
| 배지 | 높이 56 | 등급, New!, 개수 |
| 재화 표시 | 216x64 | 상단바 스태미나·젬·골드. 오른쪽에 + 버튼 원 48 |
| 레벨 배지 | 높이 40 | 슬롯의 Lv(배경 `#050D1AC7`), 프로필 레벨(배경 `#339AF0`) |

알림(!)과 선택 체크는 3.5를 따른다.

### 6.3 터치 영역
터치 영역은 최소 96x96이다. 이보다 작게 보이는 버튼(재화 + 버튼 등)은 투명 영역을 덧대 넓힌다.

### 6.4 간격
- 간격과 여백은 4, 8, 12, 16, 24, 32, 40, 48, 56, 64만 쓴다.
- 아이콘과 글자 사이 8, 같은 묶음의 항목 사이 12~16, 묶음과 묶음 사이 24~32, 화면의 큰 덩어리 사이 48~56.
- 화면 가장자리 여백: 상단바 안 16, 콘텐츠 24~48, 목록 그리드 40.
- 예외: 스크롤 목록의 아래 여백은 마지막 줄이 탭바에 가리지 않게 `탭바 높이 + 목록 간격`이다.

### 6.5 슬롯
- 장비 슬롯은 장착 칸과 보유 목록 모두 168이다. 보유 목록은 5열, 간격 40이다.
- 레벨 배지는 오른쪽 아래 안쪽(가장자리에서 20)에 놓는다. 왼쪽 위는 등급 표시, 오른쪽 위는 선택 체크와 알림 자리로 비워 둔다.

### 6.6 팝업
| 요소 | 규격 |
|---|---|
| 패널 폭 | 메시지·설정형 840, 목록형 888, 전체폭형(좌우 여백 48) 중에서 고른다 |
| 패널 | 반경 32, Surface + 테두리, 그림자 (6.8) |
| 헤더 | 높이 120, Base, 아래 구분선. 제목 H2 가운데 |
| 닫기 | 헤더 오른쪽 끝 아이콘 버튼 M(배경 투명, 아이콘 `#C9D3DF`). Dim 탭도 닫기와 같게 동작 |
| 본문 | 좌우 여백 64, 위아래 여백 56, 최소 높이 200, Body 가운데 정렬 |
| 버튼 줄 | 좌우·아래 여백 56. M 버튼 폭 352. 둘이면 [일반] [메인] 순서(사이 24), 하나면 가운데 |

### 6.7 공통 바
| 바 | 높이 | 구성 |
|---|---|---|
| 상단바 | 120 | Base, 아래 구분선. 프로필 버튼 96 → 닉네임과 레벨 배지 + EXP 바 → 재화 표시 3개 |
| 탭바 | 168 | Base, 위 구분선. 탭 5개. 선택 탭은 폭 1.9배, 표시는 3.5 |
| 화면 제목 바 | 152 | Base. 제목 H2 가운데, 양쪽에 S 버튼을 둘 수 있다 |

### 6.8 그림자
떠 있는 팝업과 Yellow 버튼에만 쓴다. Unity `Shadow` 컴포넌트로 넣는다.

| 대상 | Effect Distance | Color |
|---|---|---|
| 팝업 패널 | (0, -16) | `#00000073` |
| Yellow 버튼 | (0, -8) | `#00000059` |

## 7. 반응
- 버튼 누름, 팝업 등장, 보상 획득처럼 행동의 결과를 알려주는 곳에만 짧은 애니메이션을 쓴다. 장식 목적의 상시 점멸과 확대는 쓰지 않는다.
- 버튼에는 `ButtonFeedback`을 붙인다. 등장·강조는 `UITween`을 먼저 쓴다.
- 트윈은 `AsUI`로 unscaled 시간을 쓴다. 전투 일시정지 중에도 UI 반응이 보여야 한다.

## 8. 작업 절차

### 8.1 자료와 우선순위
1. 작업 대상의 **현재 게임 화면 캡처**와 상태별 캡처. 실제 배치와 콘텐츠의 기준이다.
2. `Assets/UIReferences/Main/`, `Assets/UIReferences/Battle/`의 `UIReferencesGuid.md`. 기능과 정보 구조의 기준이다.
3. 이 문서와 `Docs/Guide/GUIPack_CleanMinimalist.md`. 외형의 기준이다.
4. 해당 UI 프리팹과 스크립트. 이미 쓰이는 요소와 재사용할 요소를 확인한다.

자료가 서로 다르면 **현재 화면의 기능·문구와 레퍼런스의 기능 설명을 먼저 지키고**, 외형에는 이 문서를 적용한다. 확인하지 못한 부분은 추정이라고 밝힌다. 없는 기능이나 보상을 추가하지 않는다.

### 8.2 순서
| 순서 | 할 일 | 결과 |
|---|---|---|
| 1. 분석 | 현재 화면을 캡처하고 프리팹 구조를 확인한다 | 바꾸지 말아야 할 기능·정보, 이 문서와 다른 점, 확인하지 못한 부분 |
| 2. 시안 (선택) | 새 화면이나 이 문서에 없는 구성 요소가 생길 때만 만든다 | 1080x1920 시안, 바뀐 점 목록 |
| 3. 적용 | 9장 원칙으로 프리팹과 코드를 고친다 | 바뀐 프리팹·스크립트 목록 |
| 4. 확인 | Play 모드에서 다시 캡처해 11장 기준으로 본다 | 전후 캡처, 남은 차이 목록 |

- 기능·문구를 바꾸거나 새 정보를 넣을 때는 적용 전에 사람에게 확인한다.
- 이 문서에 값이 없으면 임의로 정하지 말고 12장에 올린 뒤 확인을 받는다. 정해지면 이 문서에 반영한다.
- 시선 순서를 점검한다. BattleTab은 스테이지 → 게임 시작 → 보조 메뉴, InventoryTab은 캐릭터·장착 상태 → 보유 목록 → 상세 정보 순서로 읽혀야 한다.

### 8.3 바뀐 점 보고
- **외형**: 색, 크기, 모서리, 그림자, 아이콘
- **배치**: 위치, 순서, 묶음
- **기능·정보**: 문구, 라벨, 버튼 동작. 의도하지 않은 변경이면 되돌린다.

## 9. Unity 적용 원칙
도구 사용법은 `Docs/Guide/UIWorkflow.md`를 본다.

### 9.1 색
- `ThemedGraphic`이 붙은 Graphic은 실행 중 팔레트 색으로 덮어써진다(알파만 남는다). 이런 오브젝트는 `Image.color`가 아니라 `UIColor`를 바꾼다.
- 새로 만드는 면·글자·구분선·테두리에는 `ThemedGraphic`을 붙인다. Yellow 버튼, 등급색, 게임 의미색처럼 테마와 무관한 색에는 붙이지 않는다.
- 팔레트 값은 `UIPalette.cs`에 있다. 바꾸면 그 색을 쓰는 모든 곳이 바뀌므로 먼저 사용처를 확인한다.

### 9.2 프리팹
- `.prefab` 파일을 직접 고치지 않고 Unity CLI로 고친다.
- UI 프리팹은 상위 프리팹(`MainUI`, `BattleUI`, `UIManager`) 안에 중첩돼 있다. 원본을 고친 뒤 상위 프리팹이 같은 값을 덮어쓰고 있지 않은지 확인한다.
- 실행 중에 코드가 색·크기를 정하는 요소는 프리팹이 아니라 그 코드의 직렬화 값을 바꾼다.
- 일괄 변경은 이름이 아니라 역할로 대상을 찾는다.

### 9.3 구성 패턴
| 요소 | 기준 |
|---|---|
| 팝업 | `MessagePopup` 구조를 따른다 (Dim 버튼, Mask 패널, 헤더, 본문, 버튼 줄, 맨 위 테두리). 기존 팝업은 겉모습이 6.6과 같으면 그대로 두고, 다른 이유로 고칠 때 맞춘다 |
| 카드 | Semi Rounded(Base) + 첫 자식 테두리(Divider) |
| 준비 중 버튼 | `CanvasGroup` 알파 + 자물쇠 아이콘(팩 `Icons/UI/Lock/`) |

### 10.1 화면
```text
COU_Client의 [화면 이름]을 Docs/Guide/UIStyleGuide.md 기준으로 정리해줘.
범위: [화면 전체 / 특정 영역 / 특정 상태]

2. 기능·문구를 바꾸거나 새 정보를 넣어야 하면 적용 전에 물어봐줘.

4. 결과는 8.3의 외형·배치·기능 정보로 나눠서 알려주고,
```

## 11. 검수 기준
- 화면을 축소해 봐도 주요 행동과 현재 상태가 먼저 보인다.
- 같은 역할의 버튼·카드·슬롯·배지는 화면마다 모양, 크기, 간격이 같다.
- 조작 아이콘과 콘텐츠 아이콘의 역할이 구별되고, 같은 목록의 그림 크기가 고르다.
- 긴 한글, 큰 재화 수치, 잠금·선택·비활성 상태에서 겹침이나 의미 손실이 없다.
- 팝업은 Dim 위에서 경계가 보이고, 닫기·Dim 탭·버튼이 모두 동작한다.
- 전투 배경 위 HUD의 글자와 바가 읽히고, 노치와 화면 가장자리에서 터치 영역이 유지된다.
- 기능·문구·보상은 현재 화면과 UI 레퍼런스 설명과 일치한다.

## 12. 아직 정하지 않은 규격
작업 중 만나면 임의로 정하지 말고 확인을 받는다. 정해지면 해당 장에 옮긴다.

|---|---|
| 알림 배지 테두리 | 테두리 없는 Red 원 |

| MessagePopup 본문 최대 높이 | 제한과 스크롤 없이 글 길이만큼 늘어난다 |
